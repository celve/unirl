UniRL 使用 Hydra。recipe 是 `recipes/` 下按训练域分桶的自包含 YAML 文件（`diffusion_rl/`、`vlm_rl/`、`llm_rl/`、`pe_rl/`、`unified_model_rl/`）；每次训练用 `--config-name` 选择一个：

```bash
python -m unirl.train_diffusion --config-name=<bucket>/<recipe>
```

## 组合模型

recipe 用 `_target_` 直接实例化每个运行时组件（FSDP backend、train stack、rollout engine、reward service、algorithm、data source 等）。typed config dataclass 由 `unirl` 包内的 `@register_config` 注册。注册、实例化和验证契约以生成的 [Config Package README](/en/docs/configuration/readme-reference/unirl-config) 为准。

## 参数应该放哪里

recipe 语义放在 `recipes/<bucket>/<recipe>.yaml`。集群本地路径、模型挂载、输出目录和 WandB identity 放在 launcher env var 或 CLI override（recipe 用 `${oc.env:...}` 插值）。新增 typed runtime component 时，把 config dataclass 放在靠近实现的位置，并用 `@register_config` 注册。

Override 优先级：

```text
CLI Hydra override > launcher env var > YAML default
```

## 运行时契约

Ray worker 创建前会运行 cross-component validators。实现细节和 validator 清单见生成的 [Config Package README](/en/docs/configuration/readme-reference/unirl-config)。

`sync` 和 tensor transport 解决不同问题：`sync`（`cfg.sync`）把 trainer 权重同步回 dedicated rollout engine，tensor transport（`unirl/distributed/tensor/`）是把大型 rollout 输出在 worker 间搬运的数据通道。

大作业前先运行：

```bash
python -m unirl.train_diffusion --config-name=<bucket>/<recipe> --cfg job --resolve
```
